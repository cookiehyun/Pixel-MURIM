# 온라인 대전 설계 (Pixel Murim Online)

상태: M1(동기화 핵심), M2(직접 연결 친구전) 구현됨. M3부터 남음.

## 1. 목표

| 모드 | 누가 | 연결 | 기록 |
|---|---|---|---|
| **친구전 - 직접 연결** | 방장이 방을 만들고 친구가 IP로 들어옴 | 엑셀 ↔ 엑셀 직접 (같은 와이파이, 또는 Tailscale 같은 가상 네트워크) | 없음 |
| **친구전 - 방 코드** | 방장이 방을 만들면 4글자 코드가 나오고, 친구가 코드를 입력 | 중계 서버를 거침 (설치·공유기 설정 필요 없음) | 없음 |
| **랭크전** | 혼자 "대전 찾기"를 누르면 비슷한 점수의 상대와 자동으로 붙음 | 중계 서버 | 점수(레이팅), 전적, 순위표 |

- 처음에는 1:1 대전만 만든다. 태그 대전, 관전, 재대결 투표는 나중에 한다(M5).
- Windows 엑셀과 Mac 엑셀이 서로 대전할 수 있어야 한다.

## 2. 전체 구조

```
 [직접 연결]      엑셀 A  <---- UDP ---->  엑셀 B

 [방 코드/랭크]   엑셀 A  <-- UDP -->  중계·로비 서버  <-- UDP -->  엑셀 B
                                         |
                                     SQLite (선수, 점수, 전적)
```

- **엑셀 쪽(클라이언트)**: VBA. 네트워크는 운영체제 기능을 직접 부른다.
  - Windows: `ws2_32.dll`의 UDP 소켓
  - Mac: `libc`의 BSD 소켓(`socket`, `sendto`, `recvfrom`)
  - 지금 `KeyInput`/`WinApi`처럼 `#If Mac Then`으로 나눈다.
- **서버**: 작은 Python 프로그램 하나(asyncio UDP)가 세 가지를 같이 맡는다.
  - 로비: 방 코드 발급, 랭크 대기열
  - 중계: 두 엑셀 사이 입력 패킷 전달
  - 기록: 결과, 레이팅
- **서버와의 통신도 전부 UDP 하나로 한다.** Mac VBA에는 쓸 만한 HTTP 기능이 없어서, 통신 방법을 하나로 통일하는 게 Windows/Mac 모두에서 가장 단순하다.

## 3. 대전 동기화 (넷코드)

### 방식: 입력 지연 동기화 (deterministic lockstep)
- 두 엑셀은 **키 입력만** 주고받는다. 화면, 위치, 체력은 보내지 않는다.
- 같은 입력으로 같은 계산을 하면 양쪽 화면이 똑같이 나온다. 그래서 대전 계산은 **결정적**이어야 한다(아래 5절).
- 게임은 1초에 20틱이다. 틱 N의 계산은 **양쪽 입력이 모두 도착해야** 한다.
- 지연을 감추려고 내 입력은 D틱 뒤에 반영한다(입력 지연). D는 핑으로 자동으로 정한다.
  - D = 왕복시간 / 50ms + 1, 범위 2~5
  - 국내 직접 연결 보통 2(0.1초), 중계 서버를 거치면 3~4

### 패킷
한 패킷에 최근 8틱의 내 입력을 다 담는다. 패킷 하나가 사라져도 다음 패킷으로 메워진다.

```
INPUT  <match_id> <frame> <ack> <d1 p1> <d2 p2> ... <d8 p8>
        frame = 가장 최근 입력의 틱 번호, ack = 상대 입력을 어디까지 받았는지
        d = 방향(1~9), p = 버튼 비트(A S Z X)  -> 틱당 2바이트, 패킷 약 40바이트
SYNC   <match_id> <frame> <checksum>      20틱(1초)마다: 양쪽 상태 요약값 비교
PING / PONG <time>                         지연 측정
BYE    <match_id> <reason>                 나가기
```

- 1초에 20개 정도만 보내서 데이터가 매우 적다.
- 상대 입력이 늦으면 그 틱에서 잠깐 멈춘다(프레임 멈춤). 5초 넘게 안 오면 연결 끊김 처리.
- **어긋남 확인**: 1초마다 두 캐릭터의 위치·체력·상태로 만든 요약값(checksum)을 비교한다. 다르면 "SYNC ERROR"를 띄우고 그 판은 무효로 한다. 개발 중에는 어느 틱부터 어긋났는지 기록을 남긴다.

### 왜 롤백(rollback)이 아니라 입력 지연인가
- 롤백은 늦게 온 입력을 받으면 몇 틱을 되감아 다시 계산하는 방식이라 더 매끄럽다.
- 하지만 다시 계산할 때마다 엑셀 셀 칠하기 비용이 있고, 상태 저장·복원 코드가 크다.
- 먼저 입력 지연으로 만들고, 필요하면 M5 이후에 롤백을 검토한다. 상태 복사 함수(`Fighter.CopyFighter`)는 이미 있다.

## 4. 연결 흐름

### 친구전 - 직접 연결
1. 방장: MULTIPLAYER → ONLINE → **HOST (DIRECT)**. 화면에 내 IP와 포트가 나온다(예: `192.168.0.12 : 47700`).
2. 친구: **JOIN (DIRECT)** → IP 입력.
3. 연결되면 핑 측정, 입력 지연 결정.
4. 각자 캐릭터 선택(상대가 고르는 중인 것도 보임) → 방장이 무대 선택 → 대전.
5. 판이 끝나면 같은 방에서 다시 선택 화면으로.

인터넷 너머 친구와 직접 연결하려면 둘 다 Tailscale(무료)에 들어가거나, 방장이 공유기에서 포트(UDP 47700)를 열어야 한다.

### 친구전 - 방 코드
1. 방장: **HOST (CODE)** → 서버가 4글자 코드 발급(예: `KXQM`).
2. 친구: **JOIN (CODE)** → 코드 입력.
3. 서버가 둘을 묶고, 이후 입력 패킷을 중계한다.
4. 이후는 직접 연결과 같다.

### 랭크전
1. **RANKED** → 서버 대기열에 들어감. 화면에 내 점수와 순위가 보인다.
2. 서버가 점수가 비슷한 사람끼리 묶는다. 기다릴수록 허용 범위를 넓힌다.
3. 무대는 무작위. 3판 2선승.
4. 끝나면 **양쪽 엑셀이 각각 결과를 서버에 보고**하고, 둘이 같을 때만 점수를 반영한다. 다르거나 한쪽만 보고하면 무효 처리하고 기록을 남긴다.
5. 순위표: 게임 안 화면(상위 10명 + 내 순위).

## 5. 결정성 (양쪽 계산이 똑같아야 함)

지금 코드를 확인한 결과:
- 사람끼리 싸울 때 대전 계산에 무작위 요소가 없다. `Rnd`는 CPU AI, 아케이드 대진, 랜덤 선택, 태그 CPU에만 쓴다.
  - 랜덤 선택은 대전 시작 전에 정해서 결과를 상대에게 보낸다.
- 시간 계산은 틱 수로만 한다. 실제 시간(`Timer`)은 화면 표시용으로만 쓴다.
- **고칠 것 1:** 백대시 점프 높이에 쓰는 `Sin()`은 Windows와 Mac의 계산 결과가 미세하게 다를 수 있다. 고정값 표로 바꾼다.
- **고칠 것 2:** 위치 계산에 쓰는 Double 연산(곱셈, 0.7배 감속 등)은 같은 순서로 하면 같은 결과가 나온다. 확실하게 하려면 판정에 쓰는 값만 소수 둘째 자리 등 고정 단위로 반올림하는 방법도 있다. M1 테스트에서 실제로 어긋나는지 보고 정한다.
- 이펙트, 화면 흔들림, 글자 같은 연출은 계산에 영향을 주지 않으니 달라도 된다.

## 6. 엑셀 쪽 모듈 구성

| 모듈 | 역할 |
|---|---|
| `Net.bas` (새로) | UDP 소켓 열기, 보내기, 블로킹 없이 받기. Windows / Mac 분기 |
| `Online.bas` (새로) | 온라인 상태 흐름: 연결 → 선택 동기화 → 대전 → 결과 → 다시 선택. 패킷 만들기/해석 |
| `Lockstep.bas` (새로) | 입력 지연, 입력 버퍼(틱별 양쪽 입력), 상대 입력 대기, 체크섬 |
| `Profile.bas` (새로) | 닉네임과 비밀 토큰(무작위, `data/profile.txt`에 저장). 랭크전 본인 확인용 |
| `GameLoop.bas` | 온라인 대전이면 매 틱 "양쪽 입력이 있을 때만 진행" |
| `Fighter.FeedInput` | 지금도 입력을 외부에서 넣을 수 있음. 온라인 상대 입력도 이걸로 넣는다 |
| `Screens.bas` | ONLINE 메뉴, IP·코드 입력, 대기 화면, 순위표 |

입력창(IP, 방 코드, 닉네임)은 엑셀 `InputBox`를 쓴다. 엑셀 기본 기능이라 Windows와 Mac 모두에서 돌아간다.

## 7. 서버 (`server/` 폴더, Python)

- 프로그램 하나: UDP 포트 하나에서 로비, 중계, 기록을 모두 처리.
- 저장소: SQLite 파일 하나(선수, 레이팅, 전적, 최근 경기).
- 레이팅: Elo(시작 1000, K=32). 나중에 Glicko-2로 바꿀 수 있다.
- 계정: 비밀번호 없이 "닉네임 + 엑셀이 처음 실행할 때 만든 비밀 토큰". 토큰 파일을 잃어버리면 새 계정이 된다.
- 운영: 작은 클라우드 서버 한 대. 무료 또는 월 몇천 원 수준이다. 어디에 띄울지는 정해야 한다(9절).
- 서버 코드는 이 저장소에 같이 두고, 테스트는 여기(리눅스)에서 가짜 엑셀 클라이언트로 한다.

## 직접 연결로 해 보기 (M2)

### 같은 와이파이에서
1. 두 컴퓨터 모두 최신 코드로 `ImportSrc` → 컴파일 (새 모듈: `Net`, `Online`, `Lockstep`).
2. 방장: MULTIPLAYER → ONLINE → **HOST GAME**. 화면에 IP(예: `192.168.0.12`)가 나온다.
3. 친구: MULTIPLAYER → ONLINE → **JOIN GAME** → 그 IP 입력.
4. 둘 다 캐릭터를 고르고 A(준비). 방장이 ←→로 무대를 고르고 A.
5. 대전 화면 아래에 `PING ..MS DELAY n`이 보인다. 판이 끝나면 다시 캐릭터 선택으로 돌아온다.

처음 할 때 나올 수 있는 것:
- Windows: "Windows 보안 경고 - 방화벽" 창 → **개인 네트워크 허용**.
- Mac: "네트워크 연결을 받도록 허용하시겠습니까?" → 허용. Mac이 방장이 안 되면(친구가 연결이 안 되면) Windows 쪽을 방장으로 해 본다.

### 인터넷 너머 친구와
둘 다 [Tailscale](https://tailscale.com)을 설치하고 같은 계정/네트워크에 들어간 뒤, 방장의 Tailscale IP(`100.x.y.z`)로 JOIN 한다. 또는 방장 공유기에서 UDP 47700을 방장 컴퓨터로 포트 포워딩한다.

### 엑셀 한 대로 먼저 확인하기 (테스트용 상대)
`tools/online_peer.py`는 게임을 돌리지 않고 무작위로 키를 누르는 가짜 상대다. 네트워크가 되는지만 확인할 때 쓴다(Python 3 필요).
- 엑셀이 방장: 엑셀에서 HOST GAME → 터미널에서 `python3 tools/online_peer.py join 127.0.0.1`
- 엑셀이 손님: 터미널에서 `python3 tools/online_peer.py host` → 엑셀에서 JOIN GAME → `127.0.0.1`
- `--idle`을 붙이면 가만히 서 있는다.

### 문제가 생기면
| 화면 | 뜻 / 할 일 |
|---|---|
| CANNOT OPEN PORT 47700 | 다른 프로그램(또는 다른 엑셀)이 그 포트를 쓰고 있음 |
| NO ANSWER | 방장이 기다리는 중인지, IP가 맞는지, 방화벽 허용했는지 확인 |
| CONNECTION LOST | 10초 동안 아무것도 안 옴 |
| SYNC ERROR (FRAME n) | 두 게임의 계산이 달라짐. **버전이 같은지** 확인하고, 다르지 않다면 프레임 번호를 알려주면 원인을 찾는다 |
| VERSION MISMATCH | 두 컴퓨터의 코드 버전이 다름 |

## 8. 단계 (마일스톤)

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| **M1** | 입력 지연 동기화 핵심 + 결정성 수정 | 여기서: 한 프로그램 안에 가상 엑셀 두 개를 돌려 같은 입력에 같은 결과, 패킷 손실·지연을 흉내 내도 안 어긋나는지 |
| **M2** | `Net.bas`(Windows/Mac 소켓) + 직접 연결 친구전 | 사용자: Windows PC와 Mac을 같은 와이파이에서 대전 |
| **M3** | 서버(중계 + 방 코드) | 여기서 서버 테스트 → 사용자: 방 코드로 대전 |
| **M4** | 랭크전: 대기열, 결과 보고, Elo, 순위표 | 여기서 가짜 클라이언트 여러 개로 테스트 → 사용자 실제 대전 |
| **M5** | 태그 온라인, 재대결, 연결 끊김 복구, (필요하면) 롤백 | |

## 9. 정해야 할 것

1. 서버를 어디에 띄울지(클라우드 계정, 비용 부담). M3 전에 정하면 된다.
2. 닉네임 규칙(길이, 영문만 등). 화면 폰트가 영문 대문자·숫자만 있다.
3. 순위표를 게임 안에서만 볼지, 웹페이지로도 볼지.
4. 랭크전에서 천마를 쓸 수 있게 할지(해금 기록은 각자 엑셀에 있어서 서버가 확인할 방법이 없다).
